## EXECUTIVE SUMMARY

### 1. 구축 완료 범위

- 서울 25개 자치구 전수 분류
- 프레임원 분석권역 156개와 중복 없는 Market ID 부여
- 상권 정의·경계·Taxonomy·데이터 사전·출처·API·현장조사·프로그램 연결 규칙 작성
- 각 자치구 파일 25개와 주요 상권 프로필 156개 생성
- 베이커리 상품·메뉴·장비·소비자×메뉴×시간대 구조 작성
- NotebookLM·Gemini·Claude·ChatGPT 공통 원본 및 블로그 3부 프롬프트 작성

### 2. 숫자 데이터 확보 상태

이 버전은 **구조와 공식 원천 연결을 먼저 고정한 기초판**이다. 주민등록인구·생활인구·매출·점포·임대료 숫자를 임의로 채우지 않았다. 각 상권 프로필의 숫자 필드는 **미수집** 또는 **확인 필요**이며, 데이터 확보율 표기는 **구조100·수치0**으로 통일했다.

### 3. 2026년 데이터 체계 변경 주의

- 서울시 상권분석서비스는 2026-07-03 안내 기준 2024년부터 공간 단위를 **표준단위구역**으로 변경했다.
- 행정동 단위 기존 서울 생활인구는 250m 국가표준격자 체계 전환으로 2026-07-31 이후 기존 생산이 종료되었다.
- 따라서 과거 상권코드·행정동 생활인구를 현재 프레임원 권역에 그대로 대입하지 않는다. **official_area_code + 기준연도 + geometry_version**을 함께 저장해야 한다.

### 4. 공식 상권과 프레임원 분석권역

현재 156개 권역은 모두 **프레임원 분석권역**이다. 공식 상권을 대체하거나 행정경계처럼 주장하지 않는다. 다음 적재 단계에서 서울시 상권영역 좌표(EPSG:5181)를 최신 기준으로 불러와 Market ID와 다대다 교차매핑한다.

### 6. 확보한 공식 원천

상권영역·점포/개폐업·추정매출·길단위인구·직장인구·집객시설·소비·등록인구·지하철 승하차·실시간 도시데이터·SGIS·관광데이터랩·상업업무용 매매 실거래·상가업소정보의 공식 페이지와 적재 조건을 확인했다. 상세는 [SOURCE_REGISTRY.md](./SOURCE_REGISTRY.md)와 [API_CATALOG.md](../04_API/API_CATALOG.md)를 따른다.

### 7. 아직 확보하지 못한 데이터

- 상권별 현재 보증금·월세·관리비·권리금: 공공 통합 원천 없음, 호가/실거래/현장자료 분리 필요
- 점포별 전기·배기·급배수·장비 반입·원상복구: 현장·임대인·전문가 확인 필요
- 베이커리 단독 객단가: 공식 상권별 통계 확인 전 숫자 입력 금지
- 네이버/배달앱 점포·메뉴가격: 이용약관과 수집 방식 검토 후 **온라인 메뉴가격 관찰값**으로만 저장
- 공식 상권코드와 156개 Market ID의 공간 교차매핑: 다음 적재 단계

### 8. 현장조사 우선순위

베이커리 중요도 **최상·상** 권역 131개를 우선하되, 유명 상권만 조사하지 않는다. 각 구 대표권역 1개를 먼저 조사하여 서울 전수 기준을 교정한 뒤, 프리미엄·오피스·대학가·주거·관광·시장형을 균형 있게 확대한다.

### 9. 데이터 신뢰도 문제

- A~E는 자료의 권위만이 아니라 기준시점·공간 일치 여부를 함께 본다.
- 공식 데이터라도 프레임원 권역과 공간단위가 다르면 분석값은 자동으로 A가 되지 않는다.
- 정성적 소비자·메뉴 매칭은 **프레임원 분석 의견**이며 현장조사 전에는 사실로 단정하지 않는다.

### 10. 다음 작업 우선순위

1. 서울시 상권영역 최신 geometry와 공식 코드 적재
2. Market ID ↔ 공식 상권코드 ↔ 행정동 ↔ 250m 격자 교차표 생성
3. 최근 분기 점포·매출·인구·직장·집객시설 숫자 적재
4. 각 구 대표권역 현장조사 및 경계 보정
5. 후보점포 주소 입력 시 Market ID 자동 매칭 테스트
