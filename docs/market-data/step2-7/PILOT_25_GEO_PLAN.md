**기준일:** 2026-08-27

## 1. 공통 판정

- 25개 모두 현재 `text_only / geometry none / review not_reviewed`다.
- 행정동·공식상권 목록은 이름 기반 후보이며 실제 중첩관계가 아니다.
- 공식상권 Polygon은 참조 레이어로 사용할 수 있지만 FRAMEONE Market 경계로 자동 치환하지 않는다.
- 대표점은 공식 앵커 주소·역 출구·시설 좌표를 확인하고 사람이 승인하면 확보 가능하다.
- Polygon은 `앵커확정 → 포함/제외 블록 초안 → 공식 레이어 중첩계산 → 현장/지도 검수 → 승인` 순서로만 생성한다.

## 3. Submarket 검증 양식

각 Pilot의 기존 Submarket ID와 이름은 유지하되 다음을 채운다.

| 항목 | 승인 기준 |
|---|---|
| 앵커 | 공식 주소/시설 ID 또는 역·출구 ID 확인 |
| 역 | 노선·역·출구와 실제 보행 연결 확인 |
| 도로 | 도로명과 대상 구간의 시작/종점 기록 |
| 블록 | 도로·하천·철도 등 폐합 경계로 표시 |
| 생활권 | 관찰 근거와 시간대 기록; 사실값과 분리 |
| 공식상권 | 코드·버전·중첩률 기록, 동일 개념으로 치환 금지 |
| 행정동 | PIP/면적중첩으로 산출, 이름만으로 확정 금지 |
| 공간화 | 근거 부족 시 Polygon 생성 금지, `candidate` 유지 |

## 4. Node 검증 양식

- 기존 Node ID는 유지한다.
- `node_role`을 store/anchor/station_exit/street_point/pedestrian_gate/barrier/unknown으로 재분류한다.
- 주소·좌표가 없는 노드는 검색 결과 좌표를 바로 저장하지 않고 원천, 정밀도, 검수자를 기록한다.
- 도로명 자체는 하나의 점이 아니므로 `street_point`는 교차점·구간 시작점 등 의미를 명시한다.
- 대학교명·도로명으로 잘못 분류된 기존 `node_type`은 ID를 바꾸지 않고 role만 정정한다.

## 5. Pilot 완료 기준

- 25개 모두 대표점 1개 이상 승인
- 각 Market 포함/제외 기준 문서화
- Submarket별 앵커 1개 이상 검증
- Node role 100% 분류, S/A 우선 Node 주소·좌표 검증
- 공식상권·행정동 Crosswalk에 실제 중첩률 또는 `manual_review` 사유 존재
- geometry_version·source_id·verified_by·verified_date 누락 0건
- 2023 geometry와 2024+ 지표 코드 호환 검증 전 수치 적재 0건
